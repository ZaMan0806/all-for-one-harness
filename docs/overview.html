all-for-one-harness

AI가 만든 코드와 글의 군더더기(AI-slop)를 줄이는 스킬 모음

이 저장소는 Claude Code 플러그인 마켓플레이스입니다. 저장소를 한 번 등록하면 안에 든 스킬을 Claude Code, 데스크톱 앱, claude.ai에서 같이 쓸 수 있습니다. 이 문서는 하네스가 무엇으로 이루어지는지, 그리고 이 저장소의 스킬이 언제 어떤 순서로 쓰이는지를 그림으로 설명합니다.

I.하네스란

하네스는 모델(Claude) 바깥에서 모델이 일하는 방식을 정하는 것들을 통틀어 부르는 말입니다. 크게 두 갈래입니다. 왼쪽은 모델이 읽고 따르려 하는 글이라 어길 수도 있습니다. 오른쪽은 프로그램이 직접 지키게 하는 설정이라 모델의 판단과 상관없이 작동합니다.

이름하는 일이 저장소에서는
Rule세션마다 항상 컨텍스트에 들어가는 기본 지침. CLAUDE.md, AGENTS.md, .claude/rules/에 씁니다. 아래에서 자세히 설명합니다.커밋 규칙, 스킬 가져오는 절차
Skill폴더 하나에 SKILL.md와 참고 문서. 평소에는 description만 보이고, 상황이 맞으면 본문을 읽습니다.skills/ 아래 7개
settings.json권한이나 커밋 서명처럼 프로그램이 직접 지키게 하는 설정.AI 서명 끄기 (attribution)
Hook도구를 쓰기 전후 같은 정해진 순간에 스크립트를 자동으로 실행합니다.아직 없음
Plugin스킬, 훅, 명령을 묶어 한 번에 설치하는 단위.zaman0806-skills, attention-span
Marketplace플러그인 목록. 저장소를 등록하면 안의 플러그인을 골라 설치합니다.이 저장소 전체
MCPGitHub, Figma 같은 외부 서비스를 도구로 연결하는 방식. 규칙이 아니라 손발에 해당합니다.쓰지 않음

반드시 지켜져야 하는 일은 글로 부탁하기보다 설정이나 훅으로 강제하는 편이 확실합니다. 스킬은 description이 애매하면 발동하지 않거나 엉뚱한 때 발동합니다.

규칙(Rule)

규칙은 "이 프로젝트에서는 늘 이렇게 한다"를 적은 글입니다. 사람이 새로 온 동료에게 주는 작업 안내서와 같습니다. 어디에 두느냐에 따라 적용 범위가 달라지고, 범위가 겹치면 모두 함께 읽힙니다. 좁은 범위의 규칙이 더 구체적이므로, 서로 다르면 좁은 쪽을 따르게 됩니다.

파일쓰임
~/.claude/CLAUDE.md내 모든 프로젝트에 적용. 개인 취향과 고정 요청.
CLAUDE.md, .claude/CLAUDE.md이 프로젝트에만 적용. 저장소에 커밋해서 함께 쓰는 사람과 공유합니다.
AGENTS.mdClaude 말고 Codex, Cursor 같은 다른 AI 도구도 읽는 공용 규칙 파일. 이 저장소는 규칙을 여기에 쓰고 CLAUDE.md에서 @../AGENTS.md로 불러옵니다.
.claude/rules/*.md규칙을 주제별 파일로 나눌 때 씁니다. 앞머리에 paths를 적으면 그 경로의 파일을 다룰 때만 읽힙니다. 이 저장소는 아직 쓰지 않습니다.

규칙과 스킬은 둘 다 모델이 읽는 글이지만 쓰임이 다릅니다.

규칙(Rule)스킬(Skill)
언제 읽히나세션을 시작할 때 항상상황이 description과 맞을 때만
비용늘 컨텍스트를 차지하므로 짧아야 함평소에는 한 줄이라 길어도 됨
담는 것"늘 이렇게 한다", "절대 이건 하지 않는다""이 일을 할 때는 이 순서로 한다"
예커밋에 AI 서명 금지, 버전 직접 수정 금지기술 부채 감사, 테스트 먼저 쓰기
다른 프로젝트에서그 저장소에만 있음플러그인으로 설치하면 어디서나

"규칙"이라는 말은 settings.json의 권한 규칙(permissions의 allow, deny)을 가리킬 때도 씁니다. 이것은 글이 아니라 설정이라, 모델이 어떤 명령을 실행할 수 있는지를 프로그램이 직접 막거나 허락합니다.

II.스킬의 흐름

스킬은 두 무리로 나뉩니다. 예방 스킬은 작업하는 동안 Claude가 스스로 꺼내 쓰고(ponytail-review만 직접 부름), 청소 스킬은 사람이 주기적으로 불러서 이미 쌓인 군더더기를 찾아 치웁니다.

스킬무리하는 일
karpathy-guidelines예방요청하지 않은 기능, 쓸데없는 추상화, 범위 밖 수정을 막고 가정을 먼저 말하게 합니다.
stop-slop예방상투적인 도입부, "X가 아니라 Y" 식의 대비, 군더더기 부사 같은 AI 글 패턴을 지웁니다.
verification-before-completion예방테스트나 빌드를 실제로 돌려 보기 전에는 "완료", "통과"라고 말하지 못하게 합니다.
ponytail-review예방커밋이나 PR 전에 직접 불러서, 방금 바꾼 것을 정확성부터 군더더기까지 순서대로 리뷰합니다. 코드는 고치지 않습니다.
improve-codebase-architecture청소중복 구현과 얕은 모듈을 찾아, 더 작은 인터페이스 뒤로 묶을 후보를 보고합니다.
tech-debt-audit청소저장소 전체를 아홉 관점으로 감사하고, 발견마다 파일:줄과 심각도를 붙입니다.
resolve-audit청소감사 결과 이슈를 받아 발견 하나에 커밋 하나씩 고치고 PR을 엽니다.
tdd청소동작이 바뀌는 수정이면 실패하는 테스트부터 쓰게 합니다.

III.저장소 구조

all-for-one-harness/
├── .claude-plugin/
│   ├── marketplace.json   플러그인 목록 (zaman0806-skills, attention-span)
│   └── plugin.json        버전은 워크플로가 관리 — 직접 고치지 않음
├── .claude/
│   ├── CLAUDE.md          Claude Code용 지침 (AGENTS.md를 불러옴)
│   └── settings.json      커밋 서명 끄기
├── .github/workflows/
│   └── plugin-version.yml push마다 버전을 1.0.N으로 올림
├── skills/
│   └── <스킬이름>/
│       ├── SKILL.md       name은 폴더 이름과 같아야 함
│       └── …              참고 문서, 예시
├── docs/
│   ├── HANDOFF.md         결정 기록과 다음 할 일
│   └── overview.html      이 문서
├── AGENTS.md              작업 규칙
├── README.md              스킬 표와 출처
└── LICENSE                원작자 저작권 줄 포함

IV.스킬을 더할 때

  1. 후보 저장소를 이 저장소 밖 임시 폴더에 받고, 스크립트는 실행하지 않은 채 읽습니다.
  2. 라이선스를 확인합니다. MIT·Apache는 복사하고, AGPL·GPL은 가리키기만 하며, 라이선스가 없으면 넣지 않습니다.
  3. 기존 스킬과 description이 겹치는지, 지시가 반대인지 봅니다.
  4. 폴더째 skills/로 옮기고, 예방과 청소 중 어디에 속하는지 정합니다.
  5. README의 표와 출처, LICENSE의 저작권 줄을 갱신합니다.
  6. claude plugin validate .로 검사한 뒤 스킬 하나에 커밋 하나로 올립니다.

자세한 절차는 AGENTS.md에 있습니다.
